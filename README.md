## 🧪 Ambientes isolados

Cada formação tem sua stack com versão fixada (`.fvmrc`, `.python-version`, `.nvmrc`…) e um
**Dev Container** próprio, então linguagens e versões diferentes não se misturam. Tudo funciona em
**Linux e Windows**: veja o `AMBIENTE.md` de cada formação.

| Stack | Versão fixada em | Isolamento por projeto |
|---|---|---|
| Flutter/Dart | `.fvmrc` (FVM) | um projeto Flutter por pasta |
| Python | `.python-version` | `.venv` por projeto |
| Node.js | `.nvmrc` | `node_modules` por projeto |
| Java | wrapper `mvnw`/`gradlew` | por projeto |
| .NET | `global.json` | por projeto |

## 🔧 Automação

Requer só Python 3.8+ (Linux: `python3`, Windows: `py`).

```bash
# 1. salve a página da formação (Ctrl+S, somente HTML) em _raw/<slug>/pagina.html e converta
#    (também aceita o texto copiado da página em .md)
python3 .agents/skills/dio-formacoes/scripts/dio.py parse _raw/flutter-specialist/pagina.html --slug flutter-specialist --stack flutter

# 2. gere/atualize pastas, READMEs e este índice
python3 .agents/skills/dio-formacoes/scripts/dio.py build

# 3. marque atividades concluídas (atualiza os READMEs)
python3 .agents/skills/dio-formacoes/scripts/dio.py marcar flutter-specialist "calculadora de imc"
```

### Atualização automática no push

O perfil (nível, XP), os certificados, os PDFs, o banco e os blocos deste README são atualizados
**a cada `git push`**, por um hook local. Desafios com código novo no push são marcados como entregues.
Ative uma vez por clone (Linux e Windows):

```bash
git config core.hooksPath .githooks
```

Se algo mudar, o hook faz um commit só com os arquivos gerados e interrompe o push: rode `git push`
de novo. Sem acessar o DIO: `DIO_OFFLINE=1 git push`. Pular: `git push --no-verify`.
A consulta ao DIO usa a sessão salva em `ferramentas/certificados/perfil/` (`login.py`) e respeita
um intervalo de 30 minutos. Para rodar à mão: `python3 ferramentas/certificados/atualizar.py`.
